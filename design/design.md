# roundtrip-rle-agent 設計メモ

この文書は「なぜこの設計にしたか」の記録。使い方は README を参照。

## 実証する設計パターン
**プロパティベース（往復／round-trip）オラクル**。個々の出力の正解を用意せず、
**入力に対して常に成り立つべき性質**で判定する。中でも「変換して戻すと元に戻る」往復性は最も強い性質の一つ。

## なぜこの方式を選んだか（他方式との比較）★この repo の肝
- encode の出力（"a3b2" など）の正解をいちいち書き出すのは面倒で、実装を変えると壊れる。
- 代わりに**「どんな x でも decode(encode(x)) == x」**という1本の性質を置けば、ランダムな x を大量に作って自動で突ける。encode／decode の**非対称なバグ**（片方だけずれる）が往復で必ず露見する。
- さらに「恒等変換でも往復は通る」抜け穴を、**反復入力は圧縮される**という第2の性質でふさぐ。
- 対比：golden/差分＝正解が1つに決まる時。メタモルフィック＝入力間の関係（往復もその一種）。本 repo は往復という強力なプロパティを単独で扱う列を担当。

## 確認するプロパティ
- 往復一致: すべての x で `decode(encode(x)) == x`。
- 圧縮性: 反復文字列は encode で短くなる（恒等変換よけ）。1点のみの検査だと「その入力だけ特別扱い」する実装に抜けられるため、複数の文字 × 複数の長さ（計12点）で確かめる。

## なぜ信頼できるか（オラクル自己検証）
`--selftest` で、正しい RLE は PASS、既知バグ（個数が1ずれる encode／1桁しか読まない decode／恒等変換）はそれぞれ別のプロパティ違反として FAIL になることを示す。

## 既知の限界
- 入力は英小文字を想定（"a3" の曖昧さを避けるため数字を入力に含めない）。
- プロパティを満たすこと＝特定の出力形式を保証することではない。往復さえ守れば内部表現は自由。
